第 3 章 · k 近邻法
00 · 从一个直觉说起

为什么会有 k 近邻法？

它的核心思想朴素到像一句俗语：近朱者赤，近墨者黑——想知道一个东西属于哪类，就看它周围最近的邻居是哪类。

1为什么需要它
前两章的感知机要先"训练"出 $w,b$。但现实里很多场景我们只想最直接地利用已有样本：把历史数据存着，新样本来了就近找参照，无需假设模型长什么样。
2它特别在哪
非参数方法：不预设模型形式；
懒惰学习（lazy）：没有显式训练，训练阶段只是存数据，所有计算推迟到预测时；
既能分类，也能回归。
1951提出
Evelyn Fix 与 Joseph Hodges 最早提出最近邻的思想。
1967完善
Thomas Cover 与 Peter Hart 给出理论保证：最近邻法的错误率不超过贝叶斯错误率的 2 倍（Cover–Hart 定理）。
💡
一句话：k-NN 把"记忆 + 投票"做到了极致——最简单，也最能说明"用样本直接做判断"这条路。

k 近邻法 是什么

对给定的输入实例点，先找出训练集中与它最近的 k 个点， 再用这 k 个点的类别，按多数表决预测输入实例点的类别。

→
多数表决

$\hat y$
🧩
k 近邻模型，本质上是用训练数据把特征空间划分成若干区域： 当训练集、距离度量、k 值与决策规则确定后，划分就唯一确定了。
第 3 章 · k 近邻法
01 · 三要素

k 近邻法的 三要素

想用好 k-NN，只需要确定这三件事。

1距离度量
用什么"尺子"衡量"远近"。常用欧氏距离及更一般的 $L_p$ 距离。
2k 值的选择
看几个邻居。k 小 → 模型复杂（易过拟合）；k 大 → 模型简单（易欠拟合）。通常用交叉验证选。
3分类决策规则
怎么由 k 个邻居定类别。常用多数表决，它对应经验风险最小化。
🔑
三要素一旦定下来，k 近邻法就被唯一确定了。换个距离或换个 k，等于换了一个模型。
第 3 章 · k 近邻法
02 · 距离度量

$L_p$ 距离：一套"远近"的统一公式

$L_p(x_i,x_j)=\Big(\sum_{l=1}^{n}\big|x_i^{(l)}-x_j^{(l)}\big|^{p}\Big)^{\frac{1}{p}}$
p = 1曼哈顿距离
沿坐标轴走"折线"的长度，也叫曼哈顿距离。
p = 2欧氏距离
最常用的直线距离 $\sqrt{\sum (x_i^{(l)}-x_j^{(l)})^2}$。
p = ∞切比雪夫距离
各维差值的最大值。

例 3.1：不同 p 值下谁更近？（运行结果）

Out: (4.0, '1-[5, 1]') # p=1 (4.0, '1-[5, 1]') # p=2 (3.7797631496846193,'1-[4, 4]') # p=3 (3.5676213450081633,'1-[4, 4]') # p=4

取 $x_1=(1,1)$，比较它与 $x_2=(5,1)$、$x_3=(4,4)$ 的距离：$p=1,2$ 时更近的是 $x_2$，$p\ge 3$ 时更近的变成 $x_3$——说明"谁更近"会随距离度量改变。

03 · k 值的选择

k 取多大？——复杂度与过拟合

k 很小（如 k=1）
只看最近的极少几个点。决策边界非常碎、扭来扭去，跟着噪声走。
结果模型复杂 · 过拟合
k 很大（如 k=N）
看几乎所有点。不管输入啥都预测出现最多的类，决策边界趋于平滑。
结果模型简单 · 欠拟合
⚠️
常见误区：直觉觉得"k 小 = 只看几个点 = 更简单"。其实相反！ 这里的"复杂度"指的是决策函数的灵活程度、对局部噪声的拟合能力，不是代码好不好写。

所以：k 值反映了"近似误差"与"估计误差"之间的权衡，通常用交叉验证选最优 k；二分类时一般取奇数以避免平票。

第 3 章 · k 近邻法
03 · 分类决策规则

多数表决 = 经验风险最小化

多数表决
k 个邻居中，哪个类别出现次数最多，就判为哪个类别。
$\hat y=\arg\max_{c}\sum_{x_i\in N_k(x)}\mathbb I(y_i=c)$
为什么等价于经验风险最小化
若把"误分类率"当作 0-1 损失，那么误分类率最小恰好等价于多数表决——即最小化这 k 个近邻上的经验风险。
⚖️
进一步的改进：距离加权——离得越近的邻居权重越大（如权重取 $1/d$）， 缓解"某一类样本多就总占优"的偏斜问题。

04 · 代码实战 (1)

先写一个 $L_p$ 距离函数

import math

def L(x, y, p=2):          # 计算 Lp 距离，p 默认取 2（欧氏距离）
    if len(x) == len(y) and len(x) > 1:
        sum = 0
        for i in range(len(x)):
            sum += math.pow(abs(x[i] - y[i]), p)  # 逐维累加 |x-y|^p
        return math.pow(sum, 1 / p)              # 再开 p 次方
    else:
        return 0
这段代码在做什么
严格按公式实现 $L_p$ 距离：
① 逐维算差值的绝对值，取 $p$ 次方；
② 全部相加；
③ 结果开 $p$ 次方。

改变 p 就切换了度量方式（1/2/∞）。
🧪
三个点 $x_1=(1,1),x_2=(5,1),x_3=(4,4)$，用 $p=1,2,3,4$ 分别算距离，就得到上一页的运行结果。

04 · 关键模型代码

自实现 KNN 分类器

class KNN:
    def __init__(self, X_train, y_train, n_neighbors=3, p=2):
        self.n = n_neighbors      # 近邻点个数 k
        self.p = p                # 距离度量 Lp 的 p
        self.X_train = X_train     # 训练特征（懒惰学习：只存不算）
        self.y_train = y_train     # 训练标签

    def predict(self, X):
        # 1) 先取前 n 个点填满候选列表
        knn_list = []
        for i in range(self.n):
            dist = np.linalg.norm(X - self.X_train[i], ord=self.p)  # Lp 距离
            knn_list.append((dist, self.y_train[i]))
        # 2) 扫描其余点，始终保留"最近的 n 个"（维护候选中最远的一个并替换）
        for i in range(self.n, len(self.X_train)):
            max_index = knn_list.index(max(knn_list, key=lambda x: x[0]))
            dist = np.linalg.norm(X - self.X_train[i], ord=self.p)
            if knn_list[max_index][0] > dist:
                knn_list[max_index] = (dist, self.y_train[i])
        # 3) 多数表决：统计这 n 个邻居的类别，取最多的那个
        knn = [k[-1] for k in knn_list]
        count_pairs = Counter(knn)
        max_count = sorted(count_pairs.items(), key=lambda x: x[1])[-1][0]
        return max_count

    def score(self, X_test, y_test):
        right_count = 0
        for X, y in zip(X_test, y_test):
            if self.predict(X) == y:      # 预测对了就 +1
                right_count += 1
        return right_count / len(X_test)   # 准确率

注意：predict 里每一步都要"现场算距离"——这正是"懒惰学习"的体现，也解释了为什么后面需要 kd 树来加速。

05 · kd 树

为什么需要 kd 树？

暴力搜索的问题
"懒惰学习"意味着每次预测都要和所有训练点算距离。数据一大，线性扫描极慢——是 k-NN 的主要瓶颈。
kd 树的想法
kd 树（k 维树）是把数据组织成二叉树的结构：不断用垂直于坐标轴的超平面切分空间，检索时能省去大部分数据点的搜索。
🌳
kd 树的每个结点，对应 k 维空间中的一个超矩形区域。 它不是"更好的分类器"，而是一个加速最近邻搜索的数据结构——分类结果不变，只是更快。

05 · kd 树的构造

怎么建一棵 平衡 kd 树

① 选坐标轴
依次轮换第 l 维
→
② 选中位数
以该维中位数为切分点
→
③ 切分
垂直坐标轴切成左右两半
→
④ 递归
左右子空间继续建子树
class KdNode:
    def __init__(self, dom_elt, split, left, right):
        self.dom_elt = dom_elt   # k 维向量节点（一个样本点）
        self.split   = split     # 进行分割的维度序号
        self.left    = left      # 左子空间构成的 kd 树
        self.right   = right     # 右子空间构成的 kd 树

class KdTree:
    def __init__(self, data):
        k = len(data[0])                    # 数据维度
        def CreateNode(split, data_set):
            if not data_set: return None
            data_set.sort(key=lambda x: x[split])   # 按第 split 维排序
            split_pos = len(data_set) // 2      # 中位数位置
            median = data_set[split_pos]              # 中位数分割点
            split_next = (split + 1) % k             # 轮换到下一维
            return KdNode(median, split,
                CreateNode(split_next, data_set[:split_pos]),       # 左子树
                CreateNode(split_next, data_set[split_pos+1:]))    # 右子树
        self.root = CreateNode(0, data)          # 从第 0 维开始建树

例 3.2 数据 $[[2,3],[5,4],[9,6],[4,7],[8,1],[7,2]]$ 建树后，前序遍历输出：[7,2] → [5,4] → [2,3] → [4,7] → [9,6] → [8,1]。

05 · kd 树的搜索

最近邻搜索：能剪枝就剪枝

① 向下到底
从根出发，按目标点坐标一路走到叶结点，作为"当前最近点"。
② 向上回溯
回退到每个父结点，看它是否比当前最近点更近，是则更新。
③ 判断另一支
看另一子空间 是否与"以目标点为球心的超球体"相交：相交才进去搜，否则剪掉。

运行结果（例 3.2 与大规模数据）

Out: Result_tuple(nearest_point=[2, 3], nearest_dist=1.8027756377319946, nodes_visited=4) # 目标点 (3, 4.5)

关键看点：40 万个点里找最近邻，只访问了 38 个结点——这就是 kd 树"省去大部分搜索"的威力。

06 · 习题 3.1

k=1 与 k=2 的 空间划分对比

在同一批二维实例点上，比较不同 k 值切出的区域，体会 k 与模型复杂度、准确率的关系。

观察与结论
  • k=1 时边界贴着每个点走，区域很碎，容易被单个噪声点影响 → 模型复杂、易过拟合。
  • k=2 时边界更平滑、区域更规整 → 模型更简单，泛化更稳。
  • k 越大划分越平滑，但太大会把两类混在一起 → 欠拟合。

06 · 习题 3.2 / 3.3

用 kd 树求最近邻，并推广到 k 近邻搜索

习题 3.2：求 $x=(3,4.5)^T$ 的最近邻

from sklearn.neighbors import KDTree
train_data = np.array([(2,3),(5,4),(9,6),(4,7),(8,1),(7,2)])
tree = KDTree(train_data, leaf_size=2)
dist, ind = tree.query(np.array([(3,4.5)]), k=1)
Out: x点的最近邻点是(2, 3)
习题 3.3：k 近邻搜索（算法升级）
把"最近邻"推广成"k 个近邻"：
· 用大小为 k 的当前 k 近邻点集代替"单个最近点"；
· 叶结点/回溯结点只要比当前最远点更近就插入集合；
· 判断是否进入另一子空间时，半径取"到最远点的距离"；
· 回退到根时，集合即为 x 的 k 个近邻。

同一份数据、同一个查询点，两种 kd 树实现（自实现 / sklearn）都得到 (2, 3)，结果一致。
